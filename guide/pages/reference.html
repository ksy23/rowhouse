A grid opens with one request to Salesforce, which returns its settings, your layout and the first rows together. Make a grid faster

Fewer columns help most: 20 columns take roughly twice as long as 5 to load, sort and edit. A smaller Page Size shows the first rows sooner on slow connections. And a grid of an object with more than 10,000 records sorts and searches on the server, which is slower than sorting rows already in the browser.

Honest list

Not yet

Things people ask for that Rowhouse does not do.

{{ic:search}}

Saved filters

A user's own column filters last until they leave the page; only the admin's are kept, on the grid.

{{ic:users}}

A layout per child table

Each user's layout is kept for a grid, not for the related records tabs under its rows.

{{ic:shield}}

Shield-encrypted fields

Not yet tested with Shield Platform Encryption. Sorting, searching or grouping by an encrypted field may fail.

{{ic:layers}}

Experience Cloud, multi-currency, record types

Not supported in sites; not tested with several currencies; picklists offer every active value, whatever the record type.

Questions

Questions people ask

Can I undo after saving?

No. Undo covers changes you have not saved. Saved values are the record's; use the record's field history, or the grid's audit trail if your admin turned it on, to see what they were.

What if two people edit the same record?

The last save wins, as with a list view's inline edit. Rowhouse does not lock records while they are being edited.

Do my company's validation rules, triggers and flows still run?

Yes. A save from the grid is an ordinary save. If a rule refuses a record, its cell shows the rule's message and the other records still save.

Does any data leave Salesforce?

No. Rowhouse makes no callouts and loads no outside code. Export creates a file in your own browser.

Does it work in Salesforce Classic or the mobile app?

It runs on Lightning pages in Lightning Experience, and in a narrow space it switches to record cards. It does not run in Classic or in Experience Cloud sites, and it has not yet been tested in the Salesforce mobile app.

Does a field's lookup filter apply in the grid?

Yes, when you edit the cell: a lookup with a lookup filter opens Salesforce's own lookup, which offers only the records the filter allows. A paste or an import matches a record by its Id, or by the name of a record shown in the grid; if a required lookup filter rejects that record, Salesforce refuses it when you save, and the cell says why.

Words

Glossary

API nameThe name Salesforce uses for an object or field in code and settings, such as Opportunity, CloseDate or My_Field__c. Shown in Object Manager under Field Name.
Grid ConfigurationThe record that describes one grid, built on the Grid Admin tab or in Setup. Its API name goes into the Rowhouse Grid component.
Grid Admin tabWhere grids are listed, built, changed, cloned and archived without Setup, on its Grids page, and Rowhouse's own settings are made, on its Settings page. The gear on a grid opens the same editor for that grid.
Archived gridA grid taken out of use from its menu on the Grid Admin tab, without deleting it: listed under Archived grids in the Grids page's side navigation, refused by the pages that show it, and restored from there. Deleting it for good is done in Setup.
Grid Guide tabThis guide. Everyone with Rowhouse Grid User can open it in the Rowhouse app, from the App Launcher or from the ? on a grid; its pages for admins show to Rowhouse Grid Admin.
Rowhouse appThe Lightning app, with the Rowhouse logo, that holds the Grid Guide (where it opens), Grid Admin and Grid Edit Logs tabs. Rowhouse Grid User shows it with the Grid Guide only; Rowhouse Grid Admin adds the other two.
Rowhouse GridThe Lightning component you drag onto a page in Lightning App Builder.
Unsaved editA change shown in its cell, shaded yellow, not yet saved to Salesforce.
Save barThe light-blue bar that floats at the bottom of the grid while something is unsaved: the count of unsaved changes, and under it Undo, Redo, Cancel and Save.
RangeA rectangle of cells selected with Shift, for copy, paste, fill down and clear.
Row numberA row's place in the list, 1, 2, 3 down the grid's left edge, as in a list view. Not a record number: sorting or searching numbers the rows again. A row with errors shows its error icon in its place.
Selected rowsRows ticked in the checkbox column, for Update field, Delete and actions.
Format ruleA highlight (a color, bold, an icon or a data bar) that shows when a field meets a test or a formula is true, explained in the Display Key.
Grid FilterA condition every row of a grid must meet, set by the admin, shown to users as a locked chip.
Formula columnA column the grid works out from other fields, in the syntax of a formula field. Read-only.
Record Page FieldOn a Grid Configuration, the lookup that links the grid's records to the record page it is placed on.
Grid User LayoutThe private record that keeps one user's layout of one grid; Reset layout deletes it.
Group, subtotal, Total rowRows gathered by a column's value, with figures for each group; the Total row covers the whole list.
Child tableA tab of related records under a row, itself a full grid.
ActionA flow, Apex action or quick action run from a row's menu or on the selected rows.
Grid Edit LogWhere the audit trail is kept, one entry per change, when a grid has Log Changes ticked. Entries are kept forever unless an admin chooses a period on the Grid Admin tab; then a clean-up deletes older ones each night.
Rowhouse SettingThe one record, named Default, of settings for Rowhouse as a whole: for now, how long Grid Edit Log keeps its entries. Set on the Grid Admin tab's Settings page.
Rowhouse Grid User · Diagnostics · AdminThe three permission sets: the first for everyone who uses a grid, the second for troubleshooting, the third for whoever builds grids.
