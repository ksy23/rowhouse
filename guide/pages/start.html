01

What you need

  • Lightning Experience. Rowhouse is a Lightning web component. It is placed on App, Record and Home pages; it does not run in Salesforce Classic, in Experience Cloud sites, or in the Salesforce mobile app's own list views.
  • Permission to customize the application. Grids are described by Custom Metadata records. You build them on the Grid Admin tab, or record by record in Setup; saving either way needs the Customize Application permission, which Salesforce admins have. Placing a grid on a page needs the usual permissions for Lightning App Builder.
  • Rowhouse installed in the org. If you are reading this on the Grid Guide tab, it is.
  • In a production org, until Rowhouse has passed Salesforce's security review: if saving a grid says Salesforce did not let Rowhouse save it, turn on Deploy Metadata from Non-Certified Package Versions via Apex (in Setup, type Apex Settings in the Quick Find box). Saving a grid, the guide's Build buttons and Import Grid write Custom Metadata from Apex, which Salesforce allows such a package only with this setting.
Good to know before you plan a grid

A grid shows every record of its object that the user is allowed to see. Without filters, a grid of Opportunities shows open and closed ones alike. Add Grid Filters (such as Stage does not equal Closed Won) to narrow it for everyone; users cannot remove them. Users can also search, filter by a column, and group (for example by Stage) to keep closed records together where they can be collapsed.

02

How a grid is defined

A grid is a Grid Configuration record plus the records that point to it. They are Custom Metadata, so they are settings, not data: they move between sandboxes and production in a change set or a deployment, and nobody has to re-create them by hand.

RecordHow manyWhat it holds
Grid Configuration1 per gridThe object, the sort it opens with, how many rows the first page loads, its height, frozen columns, the lookup that ties it to a record page, and what users may do: edit, export, import, delete, and whether every change is logged.
Grid Column1 per columnThe field, or a formula the grid works out; the order, whether it can be edited, sorted or wrapped, its width, and grouping and subtotal settings.
Grid Display Rule0 or moreA test (a value, a range, another field, or a formula) and a look: a fill, a text color, bold, an icon or a data bar, on a cell, or a bar on the whole row.
Grid Filter0 or moreA condition every record in the grid must meet. Users see it as a locked chip and cannot remove it.
Grid Child Table0 or moreA tab of related records under each row, shown with another Grid Configuration.
Grid Action0 or moreA flow or quick action users can run on a row, or a flow they run on the selected rows.

Every field of every record is in the configuration reference. In Setup, each field also has help text: hover over the i beside its label.

03

Give people access

Rowhouse ships three permission sets. None gives access to your records: what a user sees and changes in a grid is exactly what their profile, permission sets and sharing already allow.

{{ic:users}}

Rowhouse Grid User · required

Assign it to everyone who uses a grid, admins included. It lets them open grids, save changes, write to the audit log, keep their own layout of each grid, and read this guide in the Rowhouse app (its Grid Guide tab, the only one they see there, also opened by the ? on each grid). A profile cannot grant this access; it has to be the permission set.

{{ic:gauge}}

Rowhouse Grid Diagnostics · optional

Shows troubleshooting information: configuration warnings above each grid, and load and save timings in the browser console. Assign it while you investigate a problem, then remove it.

{{ic:layers}}

Rowhouse Grid Admin · for whoever builds grids

Adds the Grid Admin and Grid Edit Logs tabs to the Rowhouse app, beside its Grid Guide, and the gear to each grid, where grids are built and changed, and includes what Rowhouse Grid Diagnostics shows. It also shows the guide's pages for admins: this one, Configure and Features. Assign it with Rowhouse Grid User. Saving a grid also needs Customize Application.

Assign Rowhouse Grid User

  1. Open the permission set. In Setup, type Permission Sets in the Quick Find box and click Permission Sets. Click Rowhouse Grid User.
  2. Add people. Click Manage Assignments, then Add Assignment. Select each person who will use a grid, including yourself.
  3. Confirm. Click Next, leave the expiration as No expiration date, and click Assign, then Done.
  4. Give yourself Rowhouse Grid Admin. Go back to Permission Sets, click Rowhouse Grid Admin, and repeat steps 2 and 3, selecting yourself.
If someone sees nothing

A user without Rowhouse Grid User sees an error where the grid should be. A user who has it but cannot read the grid's object sees a message saying so. Check the permission set first, then their access to the object.

04

Your first grid: an account directory

A small grid of Accounts with four columns, where users can fix phone numbers, industries and owners, built on the Grid Admin tab. Ten minutes, start to finish. For a bigger example with grouping and colors, follow the pipeline review tutorial, which builds its grid in Setup, record by record.

1 · Open the Grid Admin tab

  1. Open the Rowhouse app. Click the App Launcher (the nine dots at the top left), type Rowhouse in its search box, and click Rowhouse under Apps, beside the Rowhouse logo. The app opens on its Grid Guide tab, this guide. Click the Grid Admin tab beside it. It opens on its Grids page: Your grids, cards that sum up the org's grids, and the list of every grid in use, with a side navigation on the left that narrows it to archived grids or one object's.
  2. Start a grid. Click New grid.

2 · Name it and choose the object

  1. Fill in the Grid tab and leave the rest as it is:

    API nameAccount_Directory fills in by itself
    ObjectAccount (Account) choose it from the list
    Sort byAccount Name (Name) appears once the object is chosen
    Sort directionAscending already chosen

3 · Add the columns and save

  1. Open the Columns tab. Click Columns (1). Account Name (Name) is there already: a new grid starts with its object's name.
  2. Add three more. For each row of this table, click Add column, choose the field in the new row's Field list, type the header if the table has one, and select Edit:
    FieldHeaderEdit
    Account Phone (Phone)—✓
    Industry (Industry)—✓

    A blank header shows the field's label; a lookup such as OwnerId is headed by what it points to, "Owner" (the box shows it in gray). Here it gets one that says more. Leave a dash (—) empty.

  3. Save. Click Save. The editor says Saving. This takes a few seconds…, and then a green Grid saved message appears. If Save stays gray, the list under the grid's name says what to fix first.

Rather build it in Setup? A grid is a Grid Configuration record and a Grid Column record per column; the configuration reference has every field, and the tutorials build their grids that way.

4 · Put the grid on a page

  1. Create an App page. In Setup, type Lightning App Builder in the Quick Find box and click Lightning App Builder. Click New, choose App Page, and click Next.
  2. Name it. Enter the Label Account Directory and click Next. Choose One Region and click Done.
  3. Add the grid. In the list of components on the left, find Rowhouse Grid under Custom - Managed (near the bottom of the list) and drag it onto the page. On the right, enter Account_Directory in Grid Configuration.
  4. Save and activate. Click Save. When Salesforce offers to activate the page, click Activate (or, later, click Activation… at the top right). On the Lightning Experience tab, choose the app your users work in (for example Sales), click Add page to app, and click Save.
  5. Open it. Open that app and click the Account Directory tab in its navigation bar (or the More menu).
A grid titled Account Directory with the Accounts icon, four columns (Account Name, Account Phone, Industry, Account Owner), sorted by name. Hover over a phone number: a blue pencil means you can edit it. Hover over an account name: a light gray lock, because Account Name was not made editable. For the same reason, New above the grid opens Salesforce's New Account form rather than adding a row: a new account needs its name, and the grid cannot take one.
05

Where to put a grid

{{ic:page}}

App page: the usual home

A grid on its own App page, added to an app as a tab, fills the window from its top edge to the bottom of the screen. Leave Height (px) empty for this.

{{ic:grid}}

Home page

Beside other components, set Height (px) on the Grid Configuration (for example 420), or the grid pushes the rest of the page down a full window.

{{ic:layers}}

Record page

With a Height set. Give the grid a Record Page Field and it shows only that record's related rows; without one it shows its whole list. See Contacts on an account page.

06

Moving grids between orgs

To any org, with a file. On the Grid Admin tab, Export a grid from its ▾ menu, or the grids the list shows with the Export button beside Import Grid; in the other org, click Import Grid and choose the file. The dialog shows what importing does before anything is saved, and a grid that org already has is never changed. This is the quick way to set up a demo or trial org, or an org a change set cannot reach. See Export and import grids.

From a sandbox to its production org, on your release path. Grid Configurations and everything that points to them are Custom Metadata records. Build a grid in a sandbox, then add its records to an outbound change set (they are listed under Custom Metadata Type records by type) or include them in your deployment. Deploy the Grid Configuration with its columns, rules, filters, child tables and actions together, since they point to it.

The page that shows the grid is a Lightning page, which deploys the same way as any other; a grid file holds no page.

07

Tips from building the tutorials

  • In Setup, number Sort Order in tens (10, 20, 30). A new column can then go between two others without renumbering. The Grid Admin tab numbers them for you, in the order of its list.
  • In Setup, start each record's name with the grid's name, as in Account_Directory_Phone. Records of all grids share one list in Setup, and names must be unique across all of them. The Grid Admin tab names them that way itself.
  • Use API names, without a namespace prefix: OwnerId, not Owner; My_Field__c, not its label.
  • Give yourself Rowhouse Grid Diagnostics while you build (Rowhouse Grid Admin includes it). A setting that cannot work (a misspelled field, a subtotal that does not fit) is skipped, not fatal, and the warning shows above the grid only to people with that permission set. On the Grid Admin tab the same warnings show under the editor as you change things.
  • Change a grid where it is. With Rowhouse Grid Admin, a gear beside a grid's Refresh button opens that grid's settings; save, and the grid loads again with the change.
  • Lookups show names. A lookup column, such as AccountId or OwnerId, shows the related record's name as a link and is edited by searching.
