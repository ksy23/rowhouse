Overview

The Grid Admin tab, or Setup

Every setting on this page but one can be made in two places. The Grid Admin tab, and the gear on each grid, edit a grid and all its records on one screen; Setup edits the records one at a time. Both save the same Custom Metadata records, so you can switch between them. The one exception is a column's Cell Type, which only Setup offers; the tab keeps whatever it is.

  • Who. The Rowhouse Grid Admin permission set adds the Grid Admin and Grid Edit Logs tabs to the Rowhouse app, beside its Grid Guide (where it opens and all that users see in it), and shows the gear, Grid settings, in each grid's toolbar just before Help (in a narrow space or a child table, Grid settings in the grid's menu). Saving also needs Customize Application. Without it you can open a grid and try changes, but Save, New grid, Import Grid, Clone, Archive and Restore stay gray, and the editor says why. Export needs only Rowhouse Grid Admin.
  • Checked as you go. A moment after each change, the editor checks the grid with the same code the grid itself uses. Problems that would stop it (no title, a field the object does not have, the same field twice) keep Save gray; settings the grid would leave out are listed as warnings. A field that field-level security hides from you is a warning too, not a problem: the people who can read it see its column.
  • What you can choose from. The object list shows the objects you can read. A field hidden from you is offered only if you have View Setup and Configuration, as Setup lists it for you; without it, the editor offers only the fields you can read.
  • Close or Cancel. On the Grid Admin tab, Close and Save sit at the top, beside the grid's name; from the gear, at the bottom. The button beside Save reads Close while nothing has changed and Cancel once something has. Leaving with changes, by that button or by Grid Admin or Grids above the name, asks Discard your changes?, with Keep editing and Discard.
  • Saving takes a few seconds. It is a deployment, the same as saving in Setup. Saved from the gear, the grid then loads again with the change.
  • Nothing is deleted. A saved column, display rule, filter, action or child table has an On switch instead (its Inactive field). An entry added and not yet saved can be removed. A whole grid is archived instead (its Archived field), from its menu on the Grids page; once archived, Delete in Setup in its menu under Archived grids lists its records to delete in Setup (Features › Clone, archive and delete a grid).
  • Another org. Export in a grid's menu, or Export N grids above the list, saves grids to a file; Import Grid in another org adds them and never overwrites a grid that is already there (Features › Export and import grids).
  • Fixed once saved: a grid's API name and its object. For another object, build another grid.
  • Help as you build. On the Grid Admin tab, the Grid Guide sits beside the editor's tabs and follows them: Columns shows the Grid Column, Display rules the Grid Display Rule, and so on. In a narrower window it moves under the tabs, and a table too wide for the window scrolls sideways. Open ↗ opens that record's part of this reference in a new browser tab, so the grid you are building stays as it is. Hide help folds it away, and this browser remembers; Show help, beside Close, brings it back. From the gear, the ? beside each tab's introduction opens the same part of this reference. Grid Guide, at the top of the tab, opens Get started in a new browser tab; Get started → on the Grids page opens it in place.
  • One setting for Rowhouse as a whole. On the tab's Settings page, Grid Edit Log Retention sets how long the audit trail keeps its entries (Features › Audit trail). It is the Log Retention (days) field of the Rowhouse Setting record named Default, which the first save on the tab creates and Setup then shows, but set it on the tab: saving there is what starts or stops the nightly clean-up. A period saved in Setup only, the tab says, is not acted on until it is saved on the tab.
Overview

How the records connect

Every record except the Grid Configuration has a Grid Configuration field that says which grid it belongs to. Create the Grid Configuration first, then the rest in any order. Where to find them: the Grid Admin tab, or Setup › Custom Metadata Types › type › Manage Records.

Record 1 of 6

Grid Configuration

One per grid. Its Label is the grid's title, and its API name (Grid Configuration Name) is what you type into the Rowhouse Grid component.

{{fields:Grid_Configuration__mdt}}
Defaults worth knowing

Page Size blank loads the first 200 rows, then 2,000 at a time up to 10,000 as the grid opens, then more as users scroll, up to 100,000. Height blank fills the window. A Height under 160 is treated as 160. Show Row Numbers starts selected, so the rows are numbered, as a list view's are. Allow Inline Edit, Allow New Records and Allow CSV Export are selected by default; Allow Mass Delete, Allow Import and Log Changes are not, because each can change many records at once. Allow Import also needs Allow New Records, since an import creates a record for each row without an Id; with Allow New Records off the grid offers no import.

On a record page: Record Page Field

Placed on a record page, a grid with a Record Page Field shows only the records whose field points to that page's record, like a related list: a Contacts grid with AccountId, on Account pages, shows that account's contacts. An import there fills the field in on every record it creates. On the Grid Admin tab the list offers the object's lookups to one object; in Setup any lookup of the grid's object works. The page must be of an object the lookup points to: on another object's page the grid says so instead of showing rows. On App and Home pages, or with the field blank, the grid shows its whole list.

Record 2 of 6

Grid Column

One per column, left to right by Sort Order. A column the user cannot read (field-level security) is left out for that user, silently.

{{fields:Grid_Column__mdt}}
Who can edit a column

All four must be true: the configuration's Allow Inline Edit is selected; the column's Editable is selected; the user can edit the object and the field; and the field can be edited at all (formulas, roll-ups, auto-numbers and system fields never can, nor can rich text). Long text is edited in a text area that first reads the whole value, however long.

Lookups

For a lookup or owner field (AccountId, OwnerId), the cell shows the record's name as a link and is edited by searching. Users need read access to the target object's name to edit it. Without a Column Label the column is headed by what it points to, as a record page heads it: "Account", "Owner", not "Account ID". A lookup field with a lookup filter is edited with Salesforce's own lookup, which applies the filter. The list ends with New Account (the target object) for users who may create one.

A field of a related record

Put the lookups first, as a report or a formula does: Account.Industry on a Contact grid, Account.Owner.Email, or My_Lookup__r.Status__c for a custom lookup. Up to five lookups, each pointing to one kind of record. On the Grid Admin tab, choose the lookup in the Field list (Account >), then the field under it. Without a Column Label the column is headed Account: Industry. Edits are saved to the related record (Features › Fields of a related record). In Setup, Default Sort Field, Grid Display Rule and Grid Filter fields take the same form; on the Grid Admin tab their lists offer the grid's own fields, and show one set in Setup. A path that cannot work is left out with a warning.

Formula columns

Leave Field API Name blank and fill in Formula, Formula Type and Column Label: the grid works the value out for each row as it reads the rows, in the syntax of a formula field (see Formulas). Decimal Places sets the places of a number, currency or percent result (2 when blank). A formula column is read-only and cannot be sorted, grouped, filtered, searched or subtotaled; it exports with the rest. At most 10 formulas a grid, columns and display rules together.

Child total columns

Leave Field API Name blank and fill in Child Table (a Grid Child Table of the same grid), Child Total (sum, average, min, max or count) and, except for a count, Child Field (the child field to total), with a Column Label: each row then shows what its related records add up to, such as an account's number of contacts. It follows the child table's own filters. Read-only, and it cannot be sorted, grouped or filtered. A row's total is left blank when it cannot be worked out: when the child table's filter tests a field the user cannot read, or when the row has more related records than Salesforce lets one request read. At most five per grid. On the Grid Admin tab, Add child total column.

Record 3 of 6

Grid Display Rule

One per highlight. Rules are tested in the browser against the values the row shows, so once a user keeps an edit, the row's other colors follow it before anything is saved; the edited cell itself stays shaded as unsaved until Save. A rule with a Formula is the exception: it is worked out on the server for the saved record, so it changes after a save.

{{fields:Grid_Display_Rule__mdt}}
When two rules apply to one cell

A style sets one of five things: the fill, the text color, the weight (bold), an icon or a data bar. For each of the five, the first matching rule wins, first meaning the lowest Sort Order. So a red-text rule, a green-fill rule and a warning icon can all show on one cell, but of two fills only the first shows. A Row rule counts for every cell in its row; put a Cell rule before it to let it show through.

  • Between: Operator Between, Value the low end and Value To the high end, both included. For numbers, dates, date/times and times. On the Grid Admin tab, choosing Between adds a second box, and, under Value.
  • Two fields: fill in Compare Field instead of Value, and the rule compares Field with that field of the same record: Amount Greater than Budget__c. Equals, Does not equal and the four comparisons; both fields of the same kind (two numbers, two dates, two text fields), but not multi-select picklists on the Grid Admin tab. The compare field need not be a column. On the tab, the list under Condition says A value; choose Field: … there instead.
  • A formula: fill in Formula, true or false, such as Amount > Budget__c * 1.1. Operator and Value are then not used, and Field is only the cell the rule colors; leave it blank, with Apply To Row, for the whole row. On the tab, choose Formula is true in Condition: a formula box takes Value's place, and Field offers None (a row rule).
Record 4 of 6

Grid Filter

One per condition every row must meet. The grid shows only the records that meet all its filters that are on; users see them as locked chips above the grid and cannot remove them.

{{fields:Grid_Filter__mdt}}
  • Operators and values are the display rules' (below), Between included: a picklist value by label or API name, a date as 2026-12-31 or TODAY-30, a lookup as a record Id or $User ("my records").
  • A filter that cannot work stops the grid with a message naming the filter. It is never skipped, as a display rule is, because skipping it would show records you meant to keep out. A user who cannot read a filter's field cannot open the grid.
  • Filters narrow; they are not security. Who can see a record is still decided by sharing and field-level security.
  • Users add their own from each column's ▾ menu, for as long as they stay on the page (see the user guide).
Record 5 of 6

Grid Child Table

One per tab under each row. The tab is a full grid of its own Grid Configuration, limited to the records whose Relationship Field points to that row.

{{fields:Grid_Child_Table__mdt}}
  • Build the child grid first: a Grid Configuration and columns for the child object, like any other grid. It need not be placed on any page.
  • Three levels at most: a grid, its child tables, and theirs. The third level has no toggle of its own.
  • Height is how tall the child grid can be under an open row, at least 160 pixels; the panel adds its tabs around it. Empty: 388 pixels under a top-level row, 168 one level down. Fewer records take less room.
  • Everything the child configuration allows works in the tab: editing, sorting, display rules, grouping, mass changes, import and actions (not Charts). An import into a tab fills in the parent on every new record.
Record 6 of 6

Grid Action

One per action. Rowhouse checks the type and the names when the grid loads; whether the flow or quick action exists is found out when someone runs it.

An object's quick action must be one of the grid's own object. A quick action is offered in the row menu only, and its Input and Asks first are not used: Salesforce's window asks its own questions. Asks first is the question before an autolaunched flow runs.

Access

Rowhouse checks that the user can read the object and the records, and holds the action's Required Permission. Salesforce does not check the user's access to a flow that Rowhouse runs, and an autolaunched flow runs in system context by default. So an autolaunched flow must name a Required Permission, a custom permission held by the people who may run it; without one it is not offered, and the Grid Admin tab will not save it. A screen flow and a quick action run with the user's own access, and the permission is optional. To make a flow respect field access too, set it to run in user context.

Apex

To run Apex from a grid, call it from an autolaunched flow: in Flow Builder, add an Action element, choose your invocable Apex action and pass it recordId. Then choose that flow here. Rowhouse doesn't run an org's own Apex itself: Salesforce keeps it out of reach of an installed package.

Cell types

Leave Cell Type blank: Rowhouse picks it from the field. These are the values it uses, should you ever need to override one. Cell Type is set in Setup only; the Grid Admin tab keeps it as it is. An unknown value stops the grid with an error naming the column.

texttextareaemailphoneurlnumbercurrencypercentdatedatetimetimecheckboxpicklistmultipicklistreferenceownerid

Numbers, currency and percent align right; checkboxes are centered; everything else aligns left. These can be edited in the grid: text, textarea, email, phone, url, number, currency, percent, date, datetime, time, checkbox, picklist, multipicklist, reference and owner. Rich text and Ids are shown read-only.

Icons and data bars

An icon goes before the cell's value: Warning icon, Error icon, Success icon, Info icon, Up arrow and Down arrow. On a Row rule it goes before the row's first value. The rule's Label is what the icon means, for screen readers and in its tooltip. A Data bar draws a bar behind a number, as long as the value's place between the lowest and the highest loaded value, on a scale that always includes zero; Cell rules on number, currency and percent columns only. The rule's condition decides which cells have a bar, so Is not blank gives every number one.

With Apply To set to Row, a fill tints the whole row lightly and draws a 4-pixel bar in the same color at the row's left edge. Formulas

Formula columns and formula display rules use the syntax of a Salesforce formula field: the same functions, operators and field names, checked as you type on the Grid Admin tab.

FormulaFormula TypeGives
FirstName & " " & LastNameTextA contact's full name
Amount * ProbabilityCurrencyAn opportunity's weighted amount (a percent field is a fraction in a formula: 10% is 0.1)
Account.NameTextA field through a lookup
CloseDate - TODAY()NumberDays until the close date
Amount > 250000(a display rule)True or false: whether the rule applies
  • Worked out on the server as the rows are read, so the values are the saved record's: after a save, the rows read back show the new results.
  • A field through a lookup works (Account.Name), but not through a lookup that can point to more than one object, such as the owner of a record a queue can own (a case, a lead, a custom object) or a task's Related To: use the lookup's Id instead.
  • A user who cannot read a field the formula uses does not get the column or the rule, as with a column on a field they cannot read.
  • A row the formula cannot work out (a division by zero, say) shows a blank cell.
  • A Percent result is a fraction, as in a formula field: Won__c / Total__c of 0.25 shows as 25%.
  • A formula can read $User, $Organization and custom settings ($Setup), which no field check covers: as with a formula field, put nothing in a grid formula its users should not see.

When a setting is wrong

One typo should not take a grid away from everyone, so a setting that cannot work is skipped and the grid still opens. People with the Rowhouse Grid Admin or Rowhouse Grid Diagnostics permission set see why, in a line above the grid that opens into the full list.

MistakeWhat happens
Object API Name or a Field API Name that does not exist, an unknown Cell Type, or a Record Page Field that is not a lookupThe grid shows an error naming the field, object or column. Check the spelling and use API names.
A display rule that cannot workThat rule is skipped, with the reason: an unknown field, an operator that does not suit the type, a value that is not a number or a date, a picklist value that does not exist, or a Cell rule on a field that is not a column.
A grouping or subtotal that does not fitSkipped, with the reason: a level other than 1 to 3, a level used twice, a field that cannot be grouped, a subtotal that does not suit the type. An unknown date unit is replaced by month, with a warning.
A child table or action that cannot workThat tab or action is left out, with the reason.
A formula that does not workThe Grid Admin tab shows Salesforce's own message and keeps Save gray. Saved in Setup, the column or rule is left out, with the reason.
A Grid Filter that cannot workThe grid shows an error naming the filter, for everyone: a filter is never skipped.
A rule on a field the user cannot readLeft out for that user, with no warning: a colored row would otherwise reveal a value they are not allowed to see.
